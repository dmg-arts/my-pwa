TOP-Feedback

Installation and Setup Guide

For AFROTC detachment administrators

Before you start Allow about 45 minutes for a first-time setup using Google Drive. You will need the detachment's Google account credentials and permission to create a Google Cloud project on that account. No servers, databases or software licences are required.

What this guide covers

TOP-Feedback is a web app that runs in a browser and stores every record in a Google Drive folder your detachment owns. There is no vendor, no server and no shared database — which is why setup involves your own Google account rather than an account with us.

1Decide where your data will live

Pick one. You can change later, but moving records between options is a manual export and import, so it is worth choosing correctly now.

OptionBest forWhat it means
Google Drive
RECOMMENDED		 Any detachment with more than one device Records live in a Drive folder on your Google account. Works on phones, tablets and computers, and everyone sees the same data. Needs the one-time Google setup in Part 2.
Synced folder A single office computer Points at the TOP-Feedback folder inside Google Drive for Desktop. Google's own client handles syncing. Desktop Chrome or Edge only — no phones.
This device only Trying the app out Everything stays in one browser. Nothing syncs, nothing is shared, and clearing site data erases it. Fine for evaluation — export a backup and import it once you move to Drive.
Why a browser cannot simply be pointed at a Drive folder path

Web pages have no access to the file system, and a phone has no synced Drive folder at all. The Google Drive option therefore connects through Google's own Drive service rather than a folder path. This is the reason Part 2 exists.

If you are evaluating the app, choose This device only, skip to Part 4, and come back to Part 2 when you are ready to go live. Nothing is lost — Part 8 explains how to carry your trial data across.

2Prepare the Google account

Do this once, on the Google account that will own the data. About 20 minutes.

2a. Create the folder

  1. Sign in to the detachment's Google account. Use a shared unit account. If you use a personal account, the data leaves with the person.
  2. Open Google Drive and create a folder named TOP-Feedback. The name is a convention, not a requirement, but it makes the folder obvious later.
  3. Share the folder with the cadre who need access. Give Editor access to anyone who will use the Instructor Portal.
    • Anyone with access to this folder can read every record directly, including the raw feedback. Share it only with people entitled to see all of it.
  4. Copy the folder's web address. With the folder open, copy the URL from the browser address bar. It looks like https://drive.google.com/drive/folders/1A2b3C… — you will paste this in Part 4.

2b. Allow the app to reach that Drive

Google requires any app that touches a Drive account to be registered with that account. This is free and takes about ten minutes.

  1. Go to console.cloud.google.com signed in as the same Google account.
  2. Create a new project. Name it something recognisable, such as Det 025 Feedback. Wait for it to finish creating and make sure it is the selected project in the bar at the top.
  3. Enable the Google Drive API.
    • Navigate to APIs & Services → Library.
    • Search for Google Drive API and open it.
    • Click Enable.
  4. Configure the OAuth consent screen.
    • Go to APIs & Services → OAuth consent screen.
    • If your account is on Google Workspace, choose Internal — this is simplest and needs no review.
    • If it is a standard Gmail account, choose External, then add each cadre member's Google address under Test users. Without this they will see a "not verified" block when signing in.
    • Fill in the app name and support email. Nothing else is required.
  5. Create an OAuth client ID.
    • Go to APIs & Services → Credentials → Create Credentials → OAuth client ID.
    • Application type: Web application.
    • Under Authorised JavaScript origins, add the exact address the app will be served from — see Part 3 if you do not have it yet. For example https://det025.github.io. Include the scheme, exclude any path or trailing slash.
    • Leave Authorised redirect URIs empty. The app does not use them.
    • Click Create and copy the Client ID. It ends in .apps.googleusercontent.com.
The Client ID is not a password

It identifies the app to Google and is designed to be public — it is visible in any browser that loads the page. Access is controlled by Google sign-in and by who you shared the folder with, not by keeping this string secret. There is no client secret to protect.

If you change where the app is hosted

You must add the new address to Authorised JavaScript origins or sign-in will fail with a redirect error. Changes can take a few minutes to take effect.

3Publish the app

TOP-Feedback is a folder of files with no build step and no backend, so it can be served from anywhere that serves static files.

HTTPS is required

Offline support, installation to a home screen, and Google sign-in all require a secure connection. Every hosting option below provides HTTPS automatically. Opening the files directly from a hard drive will not work.

Option A — free static hosting (recommended)

HostNotes
GitHub PagesFree. Push the folder to a repository and enable Pages in the settings. Address looks like https://yourname.github.io/top-feedback.
Netlify or Cloudflare PagesFree tier. Drag the folder onto their dashboard — no command line needed.
Your institution's web serverCopy the folder into any directory served over HTTPS.

Option B — run it from one computer

Useful for a trial, or where the detachment cannot publish to the web. Requires Python 3, which is pre-installed on macOS and Linux.

cd top-feedback
python3 serve.py              # then open http://localhost:8000

python3 serve.py --https      # needed to reach it from a phone

The --https option generates a self-signed certificate and prints an address on your local network. Phones will warn that the certificate is untrusted; accept it once. This is fine for testing, but use Option A for real use.

Whichever you choose, note the exact address

You need it for Authorised JavaScript origins in Part 2, step 5.

4Run the setup wizard

Open the app's address in a browser. On a folder that has never been set up, the wizard starts automatically.

  1. Name the detachment. This appears in the app header and on exported reports.
  2. Choose your storage option from Part 1.
  3. Connect.
    • Google Drive: paste the Client ID from Part 2b and the folder link from Part 2a, then click Sign in and connect. A Google window opens; sign in as the detachment account and grant access. The wizard confirms the folder name when it succeeds.
    • Synced folder: click Select folder… and choose the TOP-Feedback folder inside your Google Drive for Desktop directory.
    • This device only: nothing to connect.
  4. Create the folders. The wizard shows exactly what it will create and then builds it. Existing data is never touched, so it is safe to point a second device at the same folder and run the wizard again.

5Create the administrator account

A built-in administrator always works, so a detachment can never lock itself out of its own database. Your first job is to replace it for day-to-day use.

  1. From the home screen, open Database Administration.
  2. Sign in with the built-in administrator.
    • Username: Admin  (not case sensitive)
    • Password: #admin-Password
  3. Create a named administrator account for yourself, using the prompt at the top of the console. Give it both the Database admin and Instructor roles. Minimum eight characters for the password.
  4. Sign out and sign back in as your named account to confirm it works.
  5. Check that development mode is off. Go to Settings → Access. It should read "Sign-in is enforced". If it does not, turn development mode off.
The built-in password is the same for every installation

It is published in this guide and readable in the app's source. It exists as a recovery path, not as a front door — it is only as private as your Drive folder. Create named accounts and use those. Anyone who can reach your app and knows this pair can open the admin console, which is why the folder's Drive sharing is the control that actually matters.

Development mode

This setting unlocks the Instructor Portal and admin console on one device without signing in. It exists for building and demonstrating the app. It must be off before any cadet can reach the device. The app shows a warning banner on every affected screen while it is on.

6Create accounts

Everyone signs in — cadets included. That is what makes "one submission per student" mean something rather than relying on an honour system.

RolePasswordCan do
Student6+ charactersSee feedback assigned to them and submit it once.
Instructor8+ charactersCreate feedback, read responses, run analysis.
Database admin8+ charactersCreate and edit accounts, reset any password, maintain the database.

One at a time

  1. In Database Administration, click Create account.
  2. Enter the person's name. A username is suggested automatically as last.first — edit it if you prefer.
  3. Tick the roles they need, set a password, and choose their AS level.
  4. Click Save.

A whole class at once

  1. Prepare a CSV with a name column. Optional columns: username, class, password.
  2. Click Import students CSV and choose the file.
  3. A password is generated for anyone without one, in a format cadets can read off a printed list, such as tango-delta47.
  4. Download the credentials list when prompted.
The credentials list can only be read once

Passwords are stored only as hashes, so the app cannot show them again. If you close that dialog without downloading, you must reset each password individually. Download it, distribute it, then delete the file.

Resetting a forgotten password

Click the padlock icon on any account row. There is no email out of this app, so hand the new password over in person. The dialog suggests one you can read aloud.

7Install on phones and laptops

TOP-Feedback can be added to a home screen so it opens like an ordinary app, works offline, and does not need anyone to remember a web address.

DeviceHow
iPhone / iPadOpen the address in Safari, tap the Share button, then Add to Home Screen. Safari is required — other browsers on iOS cannot install web apps.
AndroidOpen in Chrome. Tap the menu, then Install app or Add to Home screen.
Windows / macOSIn Chrome or Edge, click the install icon in the address bar, or use Settings → Access → Install this app inside TOP-Feedback.
What works offline

The app opens and a cadet can fill in a form with no signal. A submission made offline is saved on the device, shown as pending in the header, and sent automatically when the connection returns. Nothing is lost. Reading existing feedback does need a connection.

8Verify and hand over

Work through this before letting cadets use the app for real.

  • The app opens over HTTPS at the address you published.
  • Settings → Access reads "Sign-in is enforced" — development mode is off.
  • A named administrator account exists and you have signed in with it.
  • The connection indicator in the header reads "ready" on a device other than the one you set up on.
  • The Drive folder contains the app's folders — open it in Drive and confirm you can see config, users, forms and the rest.
  • A test cadet account can sign in and see feedback assigned to them.
  • A test submission appears in the Instructor Portal under Responses & Analysis.
  • You have exported a backup from Instructor Portal → Database → Export backup.
  • The credentials list has been distributed and the downloaded file deleted.

Moving trial data into Drive

If you evaluated using This device only:

  1. On the trial device, go to Instructor Portal → Database → Export backup and save the JSON file.
  2. Go to Settings → Re-run setup and connect to Google Drive as in Part 4.
  3. Return to Database → Import backup, choose the file, and select Merge.

Troubleshooting

What you seeWhat to do
"Could not connect" when signing in to Google The app's address is not listed under Authorised JavaScript origins. Add it exactly, including https:// and with no trailing slash. Wait a few minutes.
Google shows "app is not verified" or blocks sign-in The OAuth consent screen is set to External and this person is not a test user. Add their Google address under Test users, or switch to Internal if you use Workspace.
The sign-in popup does not open Popups are blocked for the site. Allow them and try again.
"The folder or file was not found" The folder link is wrong, or the signed-in account does not have access to it. Re-copy the link and confirm sharing.
Header shows "offline" with a pending count Normal. Work is saved on the device and sends automatically. Click the pending badge to retry now.
A cadet cannot see a form Check its status is Open, the open date has passed, the due date has not, and the AS level matches theirs. If it targets named students, check they are on the list.
"Results withheld" instead of analysis Working as designed. Anonymous results stay hidden until three people have responded, because a single response can be traced to its author by elimination.
Nobody can sign in as an administrator Use the built-in account in Part 5, then reset the affected password.
Response counts look wrong Database Administration → Rebuild indexes. Counts are a cache and can lag; this rebuilds them from the underlying records.

Reference

What gets created in your folder

TOP-Feedback/
├── config/      detachment profile and shared settings
├── users/       accounts — cadets, instructors, admins
├── forms/       feedback form definitions
├── requests/    feedback issued to students, each with an ID
├── responses/   submitted feedback, one folder per form
├── receipts/    who submitted (kept apart from what they said)
├── reports/     exported reports
└── archive/     closed terms retained for the record

Things worth understanding before you field this

Anonymity is real, and it has a limit

On an anonymous form the cadet's username is used to verify them and to write a receipt, then discarded. The response record carries no name, and receipts live in a different folder. This is what lets the app say "two cadets still owe feedback" about responses nobody can attribute. The limit: with very few responses, a single answer can be identified by elimination, so anonymous results stay hidden until three people have responded.

Sign-in is not encryption

Passwords are stored as PBKDF2 hashes, but anyone with access to the Drive folder can read every record directly regardless of what the app shows them. Folder sharing is the real access control. Share it only with people entitled to read all of it.

The safety screen is a prompt, not a finding

Written answers are automatically checked for language about hazing, harassment, discrimination, violence, self-harm, substances and integrity. A match means read that response now — it cannot tell "we discussed hazing prevention" from "I was hazed". A clear screen is not proof that nothing was reported. Follow your detachment's own reporting procedures.

Safety alerts override the anonymity threshold

If a flagged answer appears on a form whose results are otherwise withheld, the app tells you it exists and lets you open it behind a warning that doing so may identify the author. A disclosure cannot wait for a third response to arrive.

Getting help

Diagnostics are available at Settings → Download diagnostics. The file records the app version, storage configuration and browser, and contains no feedback data — it is safe to share when asking for help.
